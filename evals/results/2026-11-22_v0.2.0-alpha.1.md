## Problems found and fixed during M6

1. **Festival due date in the past.** "Due = 14 days before the occasion" gave 24 Nov for an 8 Dec occasion seen on 28 Nov. Now: the later of today and 14 days before (automation.md, task schema, tracker). R3 and R10 re-run: pass.
2. **Offer without a browser.** The producer's partial-research offer now appears only when a browser is available; otherwise one line says the read stays queued (stage-running.md §5a). The R5 check was tightened to look for that line.
3. **Round-trip helper.** `normalise` said it treats empty lists as absent (the Sheets rule) but didn't; a task with `methods: []` failed R15. Code now matches the comment and the storage rule; the 18 fault checks still pass.
4. **Test bugs** (no plugin change): the page-render test's `[object Object]` check was a broken regex; the privacy scan now reads stored data only, not R12's notes about what it removed.

(Found in M5, before this run: the tracker page parsed `InsightFindings.confidence` as JSON, showing `[object Object]`; fixed.)

## Observations (not failures)

- The intake run said it did not validate the research output against its schema before advancing. The saved outputs were valid (checked here), but the producer's verify step (stage-running.md §6) asks for it. Watch this in live runs.
- The first monthly run listed 4 own-account top posts; the re-run listed 5. Both are allowed (`maxItems: 5`).
- With no review snippets on the web, the unattended route honestly reported reviews as `partial` and queued the browser route. Expect this on real Google Maps too.
- The installed `ig-viral` downloads Python helpers and needs `python3`, which this machine lacks; the run followed the module's rule (keep its rows, rank in the prompt) and still matched the ground truth.
