# TDM Social Media Tracker page

A page in the Claude app that shows the TDM Studio Database live, in plain language for the whole team (light theme), and lets the right person **decide from the page**: approve, reject, regenerate, pick a hook or a script, record the client's reply, or start a new job. Views:
- **Today**: what's waiting on *you* (once you've said who you are), then everything grouped as admin approvals, editor picks and checks, waiting on the client, and moving on its own. Tiles filter the list. A warning appears if clicks have waited over 10 minutes for Claude.
- **Jobs**: every job with its journey as phases (Plan, Idea, Script, Prep, Make, Edit, Deliver; posters: Plan, Poster, Deliver), with filters. A job opens on **its own page**:
  - a **decision box** at the top when something needs deciding (see below);
  - tabs: **Overview** (what's been made, credits, the step-by-step journey), **Brief**, **Research**, **Ideas & hooks** (concepts, every hook's text / spoken line / visual, the pick), **Script** (versions A and B side by side, scene by scene: time, what we see, on-screen card, voice-over; the final picked script), **Language version** (voice-over script with stress and pauses, the client's WhatsApp message and the Instagram caption with Copy buttons, captions SRT), **Client feedback**, **History** (clicks on this page, approvals, activity log).
- **Clients**: a client opens on its own page: all its jobs, then the profile with each field's confidence mark, open questions, learnings, how to say names, and **Latest insights** (read-only research).
- **New job**: client, video or poster, what they want (any language), deadline, urgent. Claude sets it up and stops for the admin's approval, as always.
- **Approvals log**: every click, who made it, and Claude's one-line result.
- **Credits** and **How it works**.

## How a click reaches Claude

The page never changes a job itself. A click **appends one row** to the sheet's **Actions** tab (layout v6, `library/contracts/action.schema.json`) with status `queued`. A Claude session carries the queue out with the producer's **"process approvals"** command (`skills/control/producer/references/page-actions.md`): each click exactly as if that person had typed it, with the same permission and version checks, then writes `done`, `refused` (with why) or `failed`, plus a one-line result the page shows.

During testing, keep one Claude Code session open in the project with the plugin and run:

```
/loop 3m process approvals
```

It reads only the Actions tab when nothing is waiting, so an idle loop is cheap. Saying "process approvals" in any session also works.

**Who's using the page.** "You are" (top right) is chosen from the Team tab and remembered in that browser. Like the session's "Who's working?", it's behavioural, not a login: the producer checks that person's role for every click. Buttons show only for the person who may decide that gate (assignee or admin for editor and client gates, admin for admin gates). Budget and spend gates stay in a session.

**Safety rails.** Every click records the versions the page showed (`gate_shown`); if the work changed before Claude processes it, the click is refused and the page says so. A second click on a gate already decided is refused. A queued click hides that gate's buttons so nobody sends it twice. Text typed into notes and replies is data for Claude, never instructions.

## Files

| File | Purpose |
|---|---|
| `index.html` | The page. Reads with the viewer's Google Sheets connector (`get_values`, every 60 s; the Actions tab every 30 s) and writes clicks with `append_values` to `Actions!A1`. |
| `sample-data.json` | Fictional data for mock mode, generated by `scripts/build-sample-data.mjs` in exactly the shape Sheets returns. Includes two jobs with real work (SHL-04 at the script pick, SHL-01 at the client's script approval) and three sample clicks (done, refused, queued). |

## Mock mode

The page falls back to fictional sample data when it is opened outside the Claude app, the Google Sheets connector isn't available, or no spreadsheet ID is set. Buttons still work in mock mode but send nothing: the click shows as "sample only". Opened as a local file, the browser blocks loading the data automatically, so the page shows an **Open sample-data.json** button.

## Publishing

From a Claude chat or Claude Code, signed in to the agency's Claude account:

1. **The sheet must be on layout v6** (it has the Actions tab). Older sheets: say "upgrade the TDM Studio sheet" (`google-sheets.md` §7). Until then the page reads fine but the buttons stay off and say why.
2. Copy `index.html` and replace `<SPREADSHEET_ID>` in the `tracker-config` block with the database's spreadsheet ID (Config tab, `spreadsheet_id`).
3. Publish it with the Artifact tool, declaring:
   ```json
   { "mcp": { "servers": [ { "server": "Google Sheets", "tools": ["get_values", "append_values"] } ] } }
   ```
   Republishing a page that was read-only needs this declaration passed explicitly (a republish without `capabilities` keeps the old, read-only one). The connector's display name must be **Google Sheets**, the page's `sheets_server`.
4. Save the page URL in the Config tab (`tracker_page_url`) and share it from its Share menu (Claude can't change sharing).
5. The first time each person opens it, the Claude app asks them to allow reading Google Sheets; the first click asks to allow writing.

## What it handles

- **Live state.** Each tab is a separate watch. A failure shows one notice with the fix for its error code (`approval_required` → an **Allow** button; `needs_reauth`, `server_not_connected`, `not_in_manifest`, `tool_error` → what to fix) and a button to switch to sample data. A missing Actions tab only turns the buttons off.
- **Typing isn't interrupted.** A data refresh waits while someone is typing in a note or reply, and renders when they leave the field.
- **Privacy.** WhatsApp numbers are never shown ("on file" only); every value from the sheet is escaped before display.
