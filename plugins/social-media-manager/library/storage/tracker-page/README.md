# TDM Social Media Tracker page

A **read-only** page in the Claude app that shows the TDM Studio Database live, in plain language for the whole team (light theme). Five views:
- **Today**: who needs to act, grouped as admin approvals, editor picks and checks, waiting on the client, and moving on its own; each job shows its current step, the next action, how long it has waited and its deadline. Tiles filter the list.
- **Jobs**: every job with its journey as phases (Plan, Idea, Script, Prep, Make, Edit, Deliver; posters: Plan, Poster, Deliver), with filters. A job page shows "Right now", the step-by-step journey with each approval, what has been made (brief, hooks pick, script pick, language version…), client feedback, credits and the activity log.
- **Clients**: profiles with each field's confidence mark, open questions, learnings, how to say names, and **Latest insights** (read-only research: findings with confidence and source, what changed, pending Instagram reads, competitors in use).
- **Credits**: Higgsfield credits per client and per open job (research money in USD/INR is never added in).
- **How it works**: every step in plain words, who approves it, and which steps are not built yet.

Changes always happen through Claude. The page never writes.

| File | Purpose |
|---|---|
| `index.html` | The page. It reads the sheet with the viewer's own Google Sheets connector (`get_values`), refreshing every 60 s. |
| `sample-data.json` | Fictional data for mock mode. Generated by `scripts/build-sample-data.mjs`, in exactly the shape Sheets returns. |

## Mock mode

The page falls back to fictional sample data when:
- it is opened outside the Claude app;
- the Google Sheets connector isn't available;
- no spreadsheet ID is set.

Opened as a local file, the browser blocks loading the data automatically, so the page shows an **Open sample-data.json** button; pick the file from this folder. Served from a folder (`npx serve` here), it loads by itself.

## Publishing (first time)

Do this from a Claude chat or Claude Code, signed in to the agency's Claude account:

1. Copy `index.html` and replace `<SPREADSHEET_ID>` in the `tracker-config` block with the TDM Studio Database's spreadsheet ID (Config tab, `spreadsheet_id`).
2. Publish it with the Artifact tool, declaring this capability:
   ```json
   { "mcp": { "servers": [ { "server": "Google Sheets", "tools": ["get_values"] } ] } }
   ```
   In Claude Code the connector can also be named by its tool prefix (`claude_ai_Google_Sheets`); the publish result confirms the display name, which must be **Google Sheets**, the value of `sheets_server` in the page config.
3. Save the page URL in the Config tab (`tracker_page_url`).
4. Share the page with the team from its Share menu. Claude can't change sharing.
5. The first time each person opens it, the Claude app asks them to allow the page to read Google Sheets. They need the Google Sheets connector connected to their account; with one shared account, it already is.

## What it handles

- **Read-only.** It calls only `get_values` on the 12 data tabs (Dashboard and Config aren't read).
- **Live state.** Each tab is a separate watch. A failure shows one notice with the fix for its error code, plus a button to switch to sample data:

  | Error | Fix the page shows |
  |---|---|
  | `approval_required` | An **Allow** button that makes one call |
  | `needs_reauth` | Reconnect Google Sheets |
  | `server_not_connected` | Add Google Sheets |
  | `not_in_manifest` | Not allowed in this view |
  | `tool_error` | Check the sheet ID and the tab headers |

- **Privacy.** It never shows WhatsApp numbers ("on file" only), and every value from the sheet is escaped before display.
